## 一、为什么需要 Agent（先解决"学了干嘛"）

Chain / RAG 是**固定流水线**：检索 → 拼 prompt → 生成，步骤写死，AI 没有选择权。

Agent 把"下一步干什么"的**决定权交给 AI**：

```
Chain：  流程你写死，AI 只是其中一个环节
Agent：  AI 自己看情况决定：要不要查资料？调哪个工具？调完再干嘛？
```

**真实用途**（这就是"学了有什么作用"）：

| 场景 | 例子 |
|---|---|
| 自动办事 | "查下上周订单，给未发货的客户发邮件" |
| 智能客服 | 自己决定查订单库 / 查物流 / 回话术 |
| 数据分析 | 自己决定先查数据库还是先算报表 |
| AI 编程助手 | 自己决定读哪个文件、改哪行代码 |

## 二、核心概念速查

| 概念 | 一句话 |
|---|---|
| Tool 工具 | 一个函数 + 名字 + 描述；**描述告诉 AI 什么时候该调它** |
| Agent | 模型 + 工具 + 循环：思考 → 调工具 → 看结果 → 再思考 |
| ReAct | Reasoning + Acting：先推理再行动，行动结果再喂回推理 |
| Middleware 中间件 | 挂在 Agent 运行流程上的"切面"（日志、限流、人工审批、改写提示词） |
| `create_agent` | LangChain 1.x 创建 Agent 的官方入口（`from langchain.agents import create_agent`） |

### ReAct 循环（面试口述版）

```
用户问题
  → AI 思考：我需要查天气（Thought）
  → 调用天气工具（Action）→ 拿到结果（Observation）
  → AI 再思考：信息够了，回答用户（Final Answer）
```

对比 Function Calling：模型原生输出"我要调哪个函数、传什么参数"，更稳定，是现在的主流。

## 三、Agent vs RAG vs Chain（一张表分清）

| | Chain | RAG | Agent |
|---|---|---|---|
| 流程 | 写死 | 写死（多一步检索） | AI 自己决定 |
| 适合 | 固定任务 | 知识问答 | 多步骤、要调外部能力的任务 |
| 例子 | 翻译 | 文档问答 | "查数据 → 写报告 → 发邮件" |

> RAG 和 Agent 经常**一起用**：Agent 决定"什么时候去查知识库"，RAG 负责查。黑马 Agent 项目里就有"向量存储服务 + RAG 总结服务"。
